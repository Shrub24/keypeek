## Why

KeyPeek is becoming a Linux/Nix-first personal downstream, but the repository does not yet record its architecture, engineering posture, development workflow, or relationship with upstream. Canonical documentation is needed before independent feature changes begin so they remain coherent and reviewable.

## What Changes

- Add concise repository documentation for the architecture and technology stack.
- Define the downstream product posture, code-quality and style rules, validation expectations, and anonymous Jujutsu change workflow.
- Record the high-level feature roadmap and the policy for evaluating upstream pull requests and forks.
- Link the canonical documentation from the project README without adding downstream doctrine to `CONTRIBUTING.md`.

## Capabilities

### New Capabilities

None. This change only establishes project documentation and development policy, so specification deltas are intentionally skipped.

### Modified Capabilities

None.

## Impact

This change affects repository documentation and contributor workflow only. It does not alter application behavior, dependencies, packaging, or public interfaces.
